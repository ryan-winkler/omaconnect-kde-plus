# Current candidate: 50-persona source audit

Date: 29 October 2026. Candidate: OmaConnect Plus, isolated `outputs/omaconnect` checkout. HEAD read for this audit: `b3bb4ff84f6349a49a8e4f36c45fd45a35a5d94f`. References below identify the working-tree source read during this audit; later edits can move line numbers.

## Method and evidence limits

**These are exactly 50 diverse synthetic personas from one model.** They are desk-analysis lenses, not recruited participants, user research, independent model reviews, clinical validation or consensus votes. ADHD, AuDHD, motor, sensory and cognitive lenses describe possible task needs. They do not predict every person's behaviour.

This audit read `AGENTS.md`, the current chooser/resolver/panel, relevant sibling components, and candidate docs. It did not run the GUI, providers, transfers, VPN controls, tests, installation or activation. It changed only this report. The parent handles any outside consultation separately; this report makes no outside-expert claim.

Each **current finding** is one of: **Gap** (a source-visible omission or mismatch), **Risk** (a plausible interaction problem requiring validation), **Guard** (a useful implemented boundary to preserve), or **Open** (acceptance is not established by the available evidence). Recorded verification is attributed to its document and was not rerun here.

**Severity/priority:** **P1** = resolve a material access/safety issue before activation if the proposed check confirms it; **P2** = fix a significant usability issue in the next focused change; **P3** = small clarity/ergonomics improvement; **V** = required validation, with no defect asserted; **Keep** = preserve and regression-check a useful guard. These labels are triage judgements, not measured scores.

**Key distinction:** Light and Dark are two render previews of one draft. They are not the icon library. Source currently gives them prominent tiles but no “Preview” heading. The five source modes already exist. The main task is to make those choices discoverable and the previews unambiguous, without building another chooser framework.
